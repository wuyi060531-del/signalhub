# 源码阅读与练习

三个动手练习，帮助读懂这个项目的核心设计。每次选一个：先写下自己的预测，再运行测试，最后对照结果。只用合成数据，在隔离环境里做。

## 1. 写一个 Python 导入与校验函数

实现一个函数：接收 JSON 对象，返回规范化后的导入记录，或者明确的校验错误。用自己编的合成数据覆盖：缺少必填字段、空正文、类型错误、非法链接、未知的可选字段。然后用同一个稳定编号导入两次，再改一个技能要求，说明原始记录和版本各是多少条。

- 提示 1：先分清“字段缺失”“空字符串”“未知值”，写出预期输出。
- 提示 2：找出导入层和规范化层各自负责哪些校验，检查错误的输入有没有被当成规范实体存下来。
- 提示 3：分别记录重复请求、失败请求、正文变化时的原始记录、实体和版本数量。
- 测试：`.venv/bin/python -m pytest -q data-pipeline-python/tests/test_normalize.py`，以及[导入和重放测试](../data-pipeline-python/tests/test_pipeline.py)。

## 2. 解释并修改一条 Java → PostgreSQL → Worker 任务链

选“手动导入”这条路径，先用自己的话画出五步：请求、任务入队、领取、处理、终态。然后补一个输入边界或写回边界的检查，对比修改前后的任务状态、attempts 和结果。

- 提示 1：API 返回 `taskId` 时，数据库里已经发生了什么？
- 提示 2：同一个任务在租约到期前后，分别由谁持有？
- 提示 3：让第二个 Worker 重新领取任务，再让旧 Worker 尝试写终态，看最终状态和规范实体。
- 测试：按[演示说明](PUBLIC_DEMO.md)准备隔离环境，运行 `test_pipeline.py`，再运行 `scripts/public_demo.py --verify-only`。

## 3. 改一条匹配规则，并验证缓存重算

选一个已知条件的规则边界，写出“符合”“冲突”“信息不足”三个输入和预期。改规则后，说明旧缓存是怎么失效的、什么时候重算；再用没变的输入验证不会重复计算。

- 提示 1：先分开看硬性资格的结果和软性评分的贡献。
- 提示 2：追踪列表读取旧分需要哪些输入身份，对比详情页读取的条件。
- 提示 3：分别制造一次岗位版本变化和一次算法版本变化，对比刷新前后的 `matching_status`、分数和计算次数。
- 测试：`./scripts/mvn.sh -f backend-java/pom.xml -Dtest=MatchingEngineTest test`，再在隔离库里运行 [Java 业务回归](../backend-java/src/test/java/io/signalhub/BusinessIntegrationTest.java)和合成演示。

## 读完源码后可以想想这些问题

1. 为什么原始记录和规范实体的提交边界不同？规范事务失败后，怎么证明数据可以重放？
2. 来源内的稳定编号和跨来源的规范 URL 各解决什么问题？正文变化时，怎么区分“重放”和“新版本”？
3. `SKIP LOCKED`、租约、attempts 各保护哪一步？Worker 领到任务后退出会怎样？
4. 为什么岗位、档案、规则和企业核验任何一项变化，都可能让匹配缓存失效？怎么验证刷新前后列表和详情一致？
5. 如果 JD 只写了毕业届别，怎么呈现春季到岗和实习时长？翻译失败时，怎么让用户仍能核对原文？
