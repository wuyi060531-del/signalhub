# 三个需要亲手完成的工程练习

每次选一项，先写预测，再运行测试，最后提交自己的代码、输出和解释。只用合成输入和隔离环境。原有七道挑战和学习记录由个人学习环境保管。此页只提供任务与提示。

## 1. 写一个 Python 导入与校验函数

实现一个接收 JSON 对象、返回规范化导入记录或明确校验错误的函数。用自编合成数据覆盖缺失必填字段、空正文、错误类型、非法链接和未知可选字段。完成后用同一稳定编号导入两遍，再修改一个技能要求，解释原文和版本的计数。

- 一级提示。先区分字段缺失、空字符串和未知值，写出预期输出。
- 二级提示。找出导入层和规范化层分别负责的校验，并检查错误输入是否被意外持久化为规范实体。
- 三级提示。分别记录重复请求、失败请求和正文变化的原始记录、实体及版本计数。
- 测试入口。自行编写隔离函数测试，再对照 `.venv/bin/python -m pytest -q data-pipeline-python/tests/test_normalize.py` 与 [导入和重放测试](../data-pipeline-python/tests/test_pipeline.py)。

## 2. 解释并修改一条 Java → PostgreSQL → Worker 任务链

选手动导入，先用自己的话画出请求、任务提交、领取、处理和终态五步。在独立练习分支补一个输入边界或写回边界，展示改动前后的状态、attempts 和结果。

- 一级提示。找到 API 返回 `taskId` 时数据库里已经发生的事。
- 二级提示。观察同一任务在租约到期前后由谁持有。
- 三级提示。让第二个 Worker 重新领取，再尝试旧 Worker 的终态更新，检查最终状态和规范实体。
- 测试入口。用 [独立测试环境](PUBLIC_DEMO.md) 跑 `test_pipeline.py`，再执行 `scripts/public_demo.py --verify-only`。本地学习环境可按需练 C01、C02 或 C07，使用 `learning/run.py challenge <编号>`。

## 3. 修改一项匹配规则并验证缓存重算

在独立分支选一个已知条件的规则边界，写出符合、冲突、信息不足三个输入与期望。改变规则后证明旧缓存如何失效、何时重算，再用未变化的输入验证不会重复计算。

- 一级提示。先分开检查硬资格结果和软评分贡献。
- 二级提示。追踪列表读取旧分所要求的输入身份，并比较详情读取的条件。
- 三级提示。分别制造一次岗位版本变化和一次算法修订变化，检查刷新前后的 `matching_status`、分数和计算数。
- 测试入口。`./scripts/mvn.sh -f backend-java/pom.xml -Dtest=MatchingEngineTest test`，随后在隔离库执行 [Java 业务回归](../backend-java/src/test/java/io/signalhub/BusinessIntegrationTest.java) 与合成演示。个人环境可先做 C05。

## 五个面试追问

1. 为什么原始记录和规范实体的提交边界不同？规范事务失败后，你如何证明数据可以重放？
2. 来源内稳定编号和跨来源规范 URL 分别解决什么问题？正文变化时怎么区分重放与新版本？
3. `SKIP LOCKED`、租约和 attempts 各保护哪一步？Worker 领取成功后退出会发生什么？
4. 为什么岗位、档案、规则和企业核验任一变化都可能影响匹配缓存？如何验证刷新前后列表与详情一致？
5. 如果 JD 只写毕业届别，怎么呈现春季到岗和实习时长？翻译失败时，如何让用户仍能核对原始证据？
