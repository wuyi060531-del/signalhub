# 合成演示说明

先按 [README](../README.md) 安装工具和依赖、构建 JAR，再运行：

```sh
.venv/bin/python scripts/public_demo.py
# 只跑断言并清理：
.venv/bin/python scripts/public_demo.py --verify-only
```

**隔离方式**
- 应用只绑定 `127.0.0.1:18085`，数据库只绑定 `127.0.0.1:55435`，库名固定为 `signalhub_demo_test`。端口被占用时脚本会直接退出。
- 脚本会新建私有的临时目录、随机密码和 SCRAM 认证的数据库集群，并校验数据目录、应用进程、库名和 V1–V12 迁移。
- 演示不会读取仓库里的 `.env`、正式数据库、个人档案或本地翻译模型。停止后会回收这次的临时目录。如果被异常中断，不要去结束占用这些端口的陌生进程。

**会看到什么**
- 第一次由 Java 的 HTTP API 入队，一个独立的 Python 进程运行一次 Worker tick；重复导入会命中幂等；修改正文会生成第二份原始记录和 V2。任务页可以看结果，详情页可以对比历史版本。演示是逐次 tick 来处理已知的任务，没有常驻的采集调度，之后提交的任务不会自动执行。
- 详情页能看到 84.5 分、两版原文和“春季到岗待核验”。在“投递记录”里可以看到合成 JD 的收藏和“已投递”记录，这只是模拟状态，没有向任何外部投递。
- 没有安装离线模型时，翻译接口返回 unavailable，详情页保留英文原文。付费 AI 队列返回 disabled，用量为 0。
- 合成岗位被标记为演示，默认不进入真实的列表和统计，演示结果也不能当作真实的招聘结论。
- README 里的两张截图来自本机隔离的合成环境，里面没有用户档案、真实岗位、浏览器账号、机器路径或密钥。

**手动回归**

CI 的 PostgreSQL 服务用于隔离回归，演示库不会复用它。要手动跑回归，把 `TEST_DB_URL` 和 `TEST_DATABASE_URL` 指向同一个新建的本机 `_test` 库（分别用 JDBC 和 SQLAlchemy 格式），并设置 `TEST_DB_USER`、`TEST_DB_PASSWORD`，再按 Maven verify → pytest → HTTP smoke 的顺序运行。测试会清理目标库里的测试数据，所以不要和演示同时使用同一个实例。
